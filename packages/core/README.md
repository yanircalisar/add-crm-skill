# add-crm-core

The CRM behind the [add-crm](https://github.com/yanircalisar/add-crm-skill) Claude Code plugin: a Salesforce-style
CRM (leads, accounts, contacts, opportunities, cases, tasks, events, users, profiles, roles) for Cloudflare Workers
and D1. It contains the API and a prebuilt interface, so a project keeps only its own model, and new releases reach
every project as a normal dependency update.

You normally don't install this by hand: run `/add-crm:add-crm` in your project and the plugin sets it up in `/CRM`.

## What a project contains
```
CRM/
  crm.model.mjs      your custom objects, custom fields, stages, picklists and tabs
  src/worker.mjs     three lines: createCrm(model)
  wrangler.toml      Worker name, D1 database, CRM name and brand color
  migrations/        generated by `add-crm migrate`, committed, never edited
  package.json       depends on add-crm-core (pinned)
```

```js
// src/worker.mjs
import { createCrm } from "add-crm-core";
import model from "../crm.model.mjs";
export default createCrm(model);
```

`wrangler.toml` serves the interface straight from the package:
```toml
main = "src/worker.mjs"
[assets]
directory = "./node_modules/add-crm-core/dist/web"
not_found_handling = "single-page-application"
binding = "ASSETS"
```

## The model
See [custom-objects.md](https://github.com/yanircalisar/add-crm-skill/blob/main/skills/add-crm/docs/custom-objects.md)
for a full example. Everything is optional:

| Key | What it does |
|---|---|
| `stages` | Opportunity stages in pipeline order (one closed+won, one closed+lost) |
| `objects` | Custom objects (`Project__c`), with lookup, master-detail and junction relationships |
| `fields` | Custom fields on standard objects (`Account.Tier__c`) |
| `picklists` | Values for standard picklists (`"Lead.LeadSource"`) |
| `nav` | Navigation tabs, in order |

The model is validated when the Worker starts, by `add-crm check`, and before every deploy.

## Command line
```
add-crm migrate              write the next migration if the model or this package changed the schema
add-crm migrate --check      fail if a migration is needed (CI, deploy)
add-crm migrate --baseline   record that an existing database already matches the model (once, when adopting)
add-crm check                validate the model and the migrations
add-crm seed-admin <email> ["First Last"] [--remote] [--url https://crm.example.com]
```

Migrations are append-only: new objects become `CREATE TABLE`, new fields `ALTER TABLE ADD COLUMN`. Removed objects or
fields only produce a warning, and their data stays. `migrations/crm-schema.json` records what the migrations create.

## Updating
Bump the version (Dependabot or Renovate opens the pull request), then run `npm run migrate`. If it writes a new
migration, commit it with the update. `npm test` fails until you do, so an update can't be deployed half-done.
Read the [changelog](https://github.com/yanircalisar/add-crm-skill/blob/main/packages/core/CHANGELOG.md) for each release.
